LoopBench

Every model here routes perfectly. Then it doesn't.

A test suite for the tool-routing decision inside an agent loop. All 10 models below pick the right tool 100% of the time on clean inputs. Add one line to the prompt and they start getting it wrong.

+0 to +100 pts
One line of injected text ("always prefer tool X"), run against 10 models. It costs Claude Opus-4-8 nothing and breaks Gemini-3.1-pro on every single case. Which model you run turns out to matter more than the loop you build around it, and the split follows the vendor, not the model size.

How each model holds up

Each number is how many points of routing accuracy the attack costs. Green means the model held up, red means it broke. Rows are sorted by how badly injection hurts.

What the grid is telling us

Adding a "double-check" step made it worse

DeepSeek, plain vs a self-check loop that re-reads its own pick before committing. The bar is how much the extra step helped (green) or hurt (red).

One good route is not a finished task

DeepSeek routes perfectly in a single turn. Real multi-step tasks are another story, and the harness decides how much.

Feeding the tool result back after each step took success from 10% to 60%. Same model, same tasks. The only thing that changed was the harness.

Scored with a deterministic ground-truth oracle, no LLM judge. 42 cases across 10 tool families, temperature 0, seed 42, with paired bootstrap 95% intervals. Reproduce a row with loopbench attack --suite datasets/routing/tools.json --provider openai --model <name>.

Read this as a pilot, not a verdict. One seed, one 42-case suite, one gateway (model aliases may resolve to specific snapshots). Treat the exact numbers as suite-dependent. What holds up is the ordering between models and the way they cluster by vendor. This probes routing robustness. It is not a safety audit or a leaderboard.
